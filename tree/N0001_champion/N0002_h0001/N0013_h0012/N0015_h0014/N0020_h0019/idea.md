## §1 — Survey: multi-branch / multi-view matching and ensemble readouts in counting (verified IDs; no gating literature; no temperature/entropy cited)

All IDs below were verified to resolve on 2026-09-21 (abstract + full text/code checked). The point of this survey is the STRUCTURE of evidence fusion across branches, not exemplar gating: counting repeatedly improves when separate match/regression branches compute their own evidence and a learned fusion combines them, rather than one selection step picking between them.

1. MCNN multi-column counting — Zhang et al., CVPR 2016, doi:10.1109/CVPR.2016.70 (verified: CVPR open-access page + IEEE Xplore record + HKU registry all resolve to the same title/pages 589–597). Core claim confirmed — three CNN columns with different receptive fields learn scale-adaptive features and their outputs are fused into the final density map; each column sees the same image through its own filters and the combination (not any one column, not a selection between columns) carries the gain. Relevance: the canonical precedent that separately parameterized branches + late fusion beat a single shared path on counting; ExLanes is that structure at the exemplar-match level (three separately projected similarity lanes + learned fusion). Difference: MCNN branches differ by receptive field on the image; ExLanes branches differ by projection pair on the query/key match — same fusion moral, new site.
2. Switch-CNN — arXiv:1708.00199 (Sam et al., CVPR 2017; verified: arXiv abs page resolves, v1 2017-08-01 / v2 2017-08-03, title/abstract/authors confirmed; official code https://github.com/val-iisc/crowd-counting-scnn). Core claim confirmed — three CNN regressors with different architectures plus a switch that relays each patch to one regressor; the multi-regressor structure (not any single regressor) handles intra-scene density variation. Relevance: independent confirmation that one match path is insufficient and K parallel paths help — and a cautionary contrast: Switch-CNN SELECTS one path per patch, which is exactly the operation our measurements show is vacuous here (indistinct exemplars, variance 0.0134), so ExLanes FUSES instead of selecting. Difference: selection vs learned fusion is the entire bet of this card.
3. MSCNN multi-scale blobs — arXiv:1702.02359 (Zeng et al., 2017; verified: arXiv abs page resolves, submitted 2017-02-08, abstract confirmed — multi-scale blobs generate scale-relevant features in a single-column architecture). Relevance: shows branch-diversity can live inside compact parallel filter sets fused downstream rather than in separate towers — licenses ExLanes' cheap form (three 128->32 query convs + three 256->32 key linears, ~37k params) instead of three full towers. Difference: MSCNN branches differ by kernel scale on features; ExLanes branches differ by learned projection on the query-key match.
4. HydraCNN / CCNN perspective-free counting — Onoro-Rubio & Lopez-Sastre, ECCV 2016 ("Towards perspective-free object counting with deep learning"; no arXiv ID — cited as proceedings only; official code https://github.com/gramuah/ccnn verified live). Core claim confirmed via the survey record — a pyramid of image patches feeds multiple scale-specific heads whose outputs are combined for the final count, incorporating multi-scale information without explicit geometric correction. Relevance: second independent precedent for multi-head evidence + combination as the load-bearing structure in counting. Difference: HydraCNN varies the INPUT scale per head; ExLanes varies the PROJECTION per lane on a fixed input — orthogonal diversification axis, same combination moral.

What the survey decides: no surveyed work builds per-exemplar similarity lanes with own query/key projections fused by a learned convolution and NO over-K softmax; the fusion-instead-of-selection structure at the exemplar-match site is unclaimed in this lineage. Pure-mathematics lens: when K logits are near-identical (variance 0.0134), softmax-over-K output ≈ mean regardless of temperature, so any selection path is provably near-constant and its gradient carries no K-contrastive signal — removing it and fusing separate maps is the only direction with nonzero information. Champion-lineage lens: SimPrior (H0001) proved stacked match evidence ([top1, cons]) fused by a learned conv works; ExLanes generalizes that structural class from 2 stacked consensus channels to 3 stacked per-exemplar channels with own projections. Counter-intuitive/low-cost lens: stop trying to pick the best of three identical exemplars — keep all three, project them differently, let fusion sort it out (~37k params, ~20 min if dud).

## §2 — Exact mechanism: ExLanes separate-lane fusion readout

### 2.1 The measured vacuity (the raison d'être, with numbers)

Inference-only reads on the N0015 checkpoint (val): K=3 exemplars MUTUALLY INDISTINCT — mean logit variance across K per cell 0.0134; top1 similarity mean -0.125 (weak match). Consequence: the K-softmax in `SimPrior.forward` (model.py:230, `W = (S / temp).softmax(dim=1)`) outputs near-uniform weights whatever the temperature, so `cons = (W*S).sum` (model.py:232) ≈ mean(S) and the top1/cons stack (model.py:233) carries no selection information. H0018's refutation (lingain futility-halt, w_lin=+0.14 engaged-but-harmful everywhere) closed the last gain-form avenue; readout-side energy avenues are 4-straight harmful/null since H0014. The remaining measured-but-untried lever is the SELECTION structure itself: replace vacuous selection with diversified fusion.

### 2.2 Exact math (minimal honest form)

Inputs read at the same site as SimPrior: `fine` (B,128,96,96) from `CountingHead.forward` (model.py:167), `e` (B,K=3,256) from the exemplar encoder (model.py:170). For each lane k in {0,1,2}, with FULLY OWN projections (no sharing — see §3):

```
q_k  = F.normalize(Wqk(fine), dim=1)        # Wqk: Conv2d(128->32, 1x1, bias=False), OWN per k
p_k  = F.normalize(Wkk(e[:, k, :]), dim=-1) # Wkk: Linear(256->32, bias=False), OWN per k; e read via detached copy
S_k  = (q_k * p_k[..., None, None]).sum(dim=1, keepdim=True)
     # (B,1,96,96) cosine in [-1,1]; ONE channel per exemplar, no mhat, no gain, no temperature
L    = stack([S_0, S_1, S_2], dim=1)        # (B,3,96,96)
out  = FuseZeroInit(L)                      # FuseZeroInit: Conv2d(3->64, 1x1), weight+bias ZERO-INIT
cond_map' = cond_map + out                  # pre-decoder residual, same add site class as model.py:178-185
```

Fixed (non-learned) fusion STRUCTURE with LEARNED weights: the combination happens inside the 3->64 conv (each of the 64 outputs is a learned linear mix of the 3 lane maps); there is no explicit per-exemplar scalar anywhere — nothing to call a gate. No temperature, no softmax-over-K at all: the vacuous selection is REMOVED, not retuned. SimPrior/cellcal/peakcal paths run unchanged beside it (their `cond_map` contribution adds at the same pre-decoder site); decoder `in_ch` stays `D + cond_dim` = 192.

Parameter count: 3 × (128×32) query convs + 3 × (256×32) key linears + 3×64 fusion = 12288 + 24576 + 192 ≈ 37k. Well under the 32M mission cap.

### 2.3 The diversification argument (honest strength: MODERATE-WEAK)

The three lanes start RNG-diverse (own randomly initialized projections) and receive different keys (e_0 / e_1 / e_2, which, though mutually similar in the SHARED simprior projection, are distinct vectors). Gradient through the separate projection pairs can therefore specialize the lanes (e.g. texture vs edge vs shape matchers): lane k's loss gradient flows only through (Wqk, Wkk), never through another lane's projections, so nothing forces the three maps to stay identical. Fixed averaging is deliberately NOT used (averaging would re-collapse to the mean — the exact vacuity being removed); the learned 3->64 fusion is where combination happens, and it can weight lanes differently per output channel and per training trajectory. If the lanes learn identically (pairwise correlation ~1.0) the card is redundant by construction — that is F1, a clean refutation, not a rescue case. WEAKNESS STATED PLAINLY (see also §5): diversification-by-construction is the thinnest mechanism story in this program. There is no theorem that separately initialized projections receiving similar keys MUST specialize; the honest prior is that they might learn the same match and the fusion learns a 3-way mean — in which case this card is a ~37k-parameter no-op and deserves its refutation.

## §3 — Why-not: banned-form compliance point by point (AGENTS.md §6 bars + §11 register)

Per-exemplar SCALAR gating/reweighting and pre-condenser exemplar modification are BANNED families (§11 register, read 2026-09-21). Shared-projection reuse is banned by verdict lineage (H0006 lesson). Match-volume-as-primary-path is banned by verdicts. This design complies on every point, explicitly:

1. NO scalar multiplies any exemplar (register ban a): there is no per-exemplar scalar parameter, no learned weight vector over K, no attention weight over K, no gate of any granularity (image-global / per-exemplar / per-channel) applied to `e` or to any lane. The K dimension is fused by a learned CONVOLUTION over stacked lane channels (3->64, 192 weights) — the same structural class as the confirmed SimPrior readout, which stacks [top1, cons] (model.py:233) and fuses with a learned conv (model.py:221–222). A conv over stacked match maps is evidence fusion, not exemplar gating: it never rescales any exemplar embedding.
2. NO pre-condenser exemplar modification (register ban b): `e` is read-only. Lane keys are computed from DETACHED copies (`e[:, k, :].detach()` through own `Wkk`); the Condenser input `e` at model.py:171 is untouched, the `e_mean` path (model.py:187) is untouched, and no tensor written back into `e` exists. The Condenser path runs byte-identically with the flag on or off.
3. NO shared projections (H0006 lesson): all six projections (3 query convs, 3 key linears) are OWN to ExLanes — none shared with SimPrior `qproj`/`kproj` (model.py:218–219), Condenser `proj_in` (model.py:114), CellCal/PeakCal scalars, or each other. Cross-lane weight tying is forbidden in this card.
4. NO K-softmax / no temperature (vacuity removal): the module contains no softmax over K, no temperature divisor, no entropy term — the measured-vacuous selection (variance 0.0134) is deleted, not reparameterized. Nothing in this card cites or depends on temperature/entropy behavior.
5. NOT match-volume-as-primary-path: the card does not scale, gate, or threshold on match magnitude; lane outputs are raw cosines fused linearly. The primary path is fusion-structure change (selection → separate-lane fusion), with magnitude entering only through the learned conv weights during training.

Single-switch pluggability holds: `use_exlanes` (default false) is the sole ablation switch; flag off = parent byte-for-byte (step-0 proof above + the residual add skipped).

## §4 — Predictions, failure modes, and the 4 reads

Predictions (all conditioned on the triple bars in the header): (i) lane conv norms move off zero during training (the fusion learns a non-trivial combination); (ii) lane outputs diversify (mean pairwise lane correlation < 0.9 on val) — the diversification PROOF; (iii) dense-block recall preserved-or-up vs N0015 (the fused evidence adds match mass where the consensus mean washed it out); (iv) sparse gt<50 stays at or below 5.45 (no over-firing on background — separate lanes must not hallucinate).

F3 — quiet (lanes diverse but bars missed: MAE within noise ±0.02–0.30 short, dense flat): evidence without mass → REFUTE. All three failures refute; there is no rescue parametrization in this card (no second switch, no form swap — that would be a new hypothesis).
